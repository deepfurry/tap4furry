## Scope and security

- Migration 3 adds only `auth_challenges` and `security_events`. Migrations 1/2,
  dependency manifests/locks, Admin health behavior and River architecture are unchanged.
- CSRF is base64url HMAC-SHA256 of the raw HttpOnly session token, with a private
  production secret of at least 32 bytes. GET `/auth/csrf` requires a PostgreSQL
  session and returns no-store. Authenticated unsafe routes require exact Origin
  and this HMAC; anonymous unsafe routes require Origin. No raw session reaches JS.
- Challenges use easyhash v1.2.0 GenerateToken/HashToken/VerifyToken and indexed
  self-described SHA-256 hashes. Verification lasts 24 hours; reset 30 minutes.
  Reissuance observes a 60-second identity/purpose cooldown even after consumption,
  and invalidates the old challenge before replacement. Consumption is single-use.
- Existing-account auth writes lock the credential row first and revalidate state.
  Password hashing/verification and delivery happen outside transactions. Reset/change
  revoke all public sessions and create one replacement with the event atomically.
  Reauthentication replaces the current session and refreshes authenticated_at.
  Reset does not verify email. Session listings/revocations are restricted to owned,
  active public sessions. Security events contain only IDs, type and time.
- Reset requests return the same 202/body for existing, absent, disabled, deleted
  and password-ineligible identities, cooldown and delivery failure. A bounded
  dummy Argon2id operation is performed for every request. This is not the later
  multidimensional abuse-control system.
- Mail is a consumer-owned auth interface implemented by `internal/mail`. Delivery
  follows commit; failures do not undo a registration or lose its issued cookie.
  Local capture is confined below ignored `.local` with `os.Root`, random filenames,
  and restrictive permissions where supported. Links use fragments. No message or
  raw token is stored in a queue, normal response, log or tracked file. Production
  rejects local mode; `disabled` explicitly means no provider. No SMTP/provider
  dependency was added.
- React recovery pages clear the fragment immediately on hydration, retain it only
  in memory, and use no-referrer/no-store shells. Account controls fetch a fresh CSRF
  value for each mutation; no stored CSRF cache survives rotation.

## Deviations and remaining scope

No material deviation from P0-1B. The direct post-commit challenge-mail exception is
explicitly documented in Jobs guidance as required by the spec. The small `disabled`
adapter supports an explicitly absent production provider; it is not production
delivery. Credential-row locking additionally closes login/reset races without
holding a KDF in a transaction. No dependency or speculative domain was added.

Remaining phases are P0-1C — Google/GitHub OAuth + Account Linking, and P0-1D — Admin
Auth + Roles + Final Auth Hardening. Production delivery is still required before
production use. This unpushed commit has no remote CI run; the existing workflow's
gates were run locally. The final local commit SHA is reported in the task response.
